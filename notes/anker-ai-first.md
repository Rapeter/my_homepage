## 二、矿区安全作业系统

### Q3｜能大概介绍一下矿区安全作业系统的项目背景和架构吗？

**我的回答：**

某工业企业有不同的矿区，我们针对的是多矿区接口重复接入的问题。我负责整理各矿区的 OpenAPI 定义，运行自动生成流程，把生成结果变成可用的 MCP Tool。

我的主要工作是补充工具的安全和治理规则，包括能够调用工具的角色身份、权限分级、读写等级，以及敏感数据脱敏。

### Q4｜项目涉及 Agent → Tool → 业务系统三层链路，能具体讲一下吗？

**我的回答：**

Agent 首先收到用户的问题，对用户意图进行识别，再通过 Function Calling 调用工具。

我主要做的是工具权限设计，需要遵循最小权限原则。对于写入类工具，需要用户审批之后才能执行。

调用工具之后，由大模型整理最终答案，再传给业务系统。

### Q5｜在整条链路上，有没有做身份 Token 透传、参数白名单、入参格式校验等风险管控？

**面试官的补充追问：**

Agent 可以理解为大模型决策层，Tool 是权限执行点或策略层，最后是业务系统的数据层。比如会话有没有校验发起人的身份 Token，Tool 的入参有没有做格式校验和参数白名单？

**我的回答：**

我先确认了一下，是不是指敏感数据和业务工具权限设计这些，然后用通风机故障录入举了一个例子。

首先对照业务接口文档和 OpenAPI 定义，确认故障录入接口、请求方式，以及必填参数有没有填上。

一线操作人员大多使用自然语言，但接口文档里使用的是故障字典编码，所以需要把自然语言描述转换为对应的故障编码。我会把这些故障原因字典整理到工具的参数白名单里。

最后验收时，需要确认故障记录确实生成，不能只看消息记录或者 HTTP 200。要用查询接口确认设备、时间、矿区 ID、设备 ID 都能对上，以此确认记录确实上传成功。

### Q6｜简历提到写入工具收敛到一定数量、占比较低。为什么最终收敛到这个数量？这个数量如何确定？（具体数量已泛化）

**我的回答：**

这里说的是写入类工具。因为遵循最小权限设计，所以尽量减少写入类工具，降低发生危险操作的可能性。

**面试官的回应：**

理解为减少攻击面。

### Q7｜人工兜底具体是什么机制？

**我的回答：**

比如有写入操作时，必须进入人工审批。人工批准之后，才会调用业务系统写入数据，就是 Human in the Loop。

### Q8｜简历提到可观测性、成本、调用链追踪、预算限流和回放，这些分别是怎么实现的？

**我的回答：**

我们阅读报告时，会按矿区看模型侧的 Token Usage。有一次发现某个矿区的 Token 消耗增速明显高于其他矿区。

我去查 Trace，发现异常发生在夜间：有一个工具在短时间内被 Agent 多轮调用，每次都把工具结果塞回上下文，导致 Token 消耗和输入上下文不断增长。

定位之后，我做了三件事：

1. 如果参数没有变化，而且结果还在有效期内，就复用结果，减少 Agent 的重复调用。
2. 在 Trace 中补齐矿区和工具标签，让模型和工具两个 Span 的维度能关联起来。这样下一个统计周期就能判断，是某个矿区的问题，还是该矿区下某个工具的问题。
3. 按矿区配置 Token 预算，并在高峰期限流。简历里也提到了八点到十点这类可能的上传高峰期。

第二个周期检查时，发现 Token 增速回落，重复工具调用占比下降，正常巡检也没有受到影响。

## 三、岗位级 AI 工作助手平台

### Q17｜先不谈技术，这个助手平台主要解决什么问题？

**我的回答：**

也希望减少人工操作的负担，让他们不用再专门学习如何使用那些操作系统，尽量通过自然语言就能解决问题。

### Q18｜这个项目听起来不是一个实习生就能推动的。当时有正式员工一起合作吗？

### Q19｜所以你在这个项目中的角色是核心开发，对吗？

**我的回答：**

对，我主要负责开发，包括写 Skill，以及定义标准任务 SOP。

### Q20｜不同岗位的工作内容和专家经验都不一样，你是怎么整理各岗位工作 SOP 的？

**我的回答：**

先按岗位、矿区和任务类型收集信息。企业也提供了之前的一些流程，我们还能在他们的业务平台上查看具体任务链路。

比如一线员工发现设备有问题，需要录入时间、原因、矿区、自己的工号和其他个人信息，有时还有隐患照片。录入系统后，还要生成审批单，再由另一个人审核，整个流程比较繁琐。

我和其他同事一起把这些流程、规则和信息梳理出来，整理成 Skill。

### Q21｜选矿、设备、财务采购这些岗位方向差异很大，你觉得哪些岗位的 SOP 比较难固化或整理？

**我的回答：**

选矿、财务采购比较难整理。它们涉及计算机专业之外的知识，需要提前理解业务，知道核心痛点和业务逻辑，比如选矿的逻辑是什么。

财务采购还涉及很多公司隐私信息，需要设计信息脱敏规则，知道哪些信息 Agent 可以知道，哪些不能保存在里面，也要设计每个人的权限能查到哪里。

### Q22｜以选矿为例，你还记得当时整理出了什么标准化业务任务吗？

**我的回答：**

业务经理当时讲过选矿逻辑，但我们最后没有真正涉及这一部分。我们主要负责的是内部员工录入系统这些事情，做企业内部提效。

选矿相关内容只是让我们做一个大概的 Demo，让他们了解 Agent、Skill 和 Tool 能怎样帮助他们。

当时提供了一些选矿预算、规模大小、地区、需要哪些人等信息，做了一个大概的 Demo，但最后没有用到具体实际业务上。像真实投标、中标这些内容，不会让实习生接触。

### Q23｜那在你列的这些岗位里，究竟有哪些标准工作流最终落地了？

**我的回答：**

包括设备管理，以及各个岗位的权限分级。

### Q24｜岗位权限分级算什么标准工作任务？

**我的回答：**

这个不算工作任务，分级属于权限设计，不是最终的任务。

### Q25｜既然并不是每个岗位的任务都上线，有些只是 Demo，那么最终上线的东西是什么样的？哪些人在真实使用？

**我的回答：**

一线工人用得比较多，比如设备发生故障之后的处理。

上一个项目主要是 Agent 能力接入，这个项目会涉及多个 Agent。我会拆成设备、安全、知识三个不同的 Agent：

- 设备 Agent 只能访问设备台账和检修记录。
- 安全 Agent 只能访问相关规则和风险流程。危险级别达到一定程度后，需要立即停机、人员撤离。
- 知识 Agent 主要做历史案例和依据检索。

上面还有一个主 Agent，也就是 Supervisor，根据任务判断需要哪个 Agent 参与。固定流程里包括权限校验、工具调用和最后的审计。

### Q26｜一线工人实际怎么使用这个助手？作业过程中不太可能突然空出手和 AI 对话，这个平台是怎样嵌入工作流程的？

**我的回答：**

我们有一个群，在 企业协作平台 里面，通过调用 MCP Tool 获取里面的问题和相关信息。

一线工人也可以通过网页上传信息，我们还可以从 企业协作平台 的对话记录里查询。
