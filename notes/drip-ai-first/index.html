面试官的问题与我的实际回答

Q01｜当前是否在学校 #

面试官的问题（概括）： 你现在是在学校吗？

我的回答（概括）： 我说自己已经回到国内，目前不在学校。

Q02｜自我介绍 #

面试官的问题（概括）： 请先简单介绍一下自己。

我的回答（概括）： 我介绍了海外高校计算机相关本科和信息技术硕士背景，关注 AI 应用与 Agent 工程；通过校企合作参与某工业企业的安全作业与岗位 AI 助手项目，主要做岗位任务标准化、测试记录和问题反馈；还以“自己的开源项目”介绍了 Electron、React、TypeScript 的金融研究工作台，但没有明确说明原创与贡献关系。

Q03｜开源项目的场景与架构 #

面试官的问题（概括）： 这个开源项目具体是什么场景，解决什么问题？系统怎么做的？

我的回答（概括）： 我说它像投资 AI 助手，可以查看股票价格、K 线和比较不同公司，把能力集成到同一个界面，减少切换其他应用。

Q04｜行情数据接入 #

面试官的问题（概括）： 系统的数据源是怎么集成进来的？

我的回答（概括）： 我回答直接接了 行情数据 CLI。

Q05｜深入研究与证据报告 #

面试官的问题（概括）： 拿到数据以后，分析、深入研究和证据化报告是怎么做的？

我的回答（概括）： 我主要解释了 Skill 按需读取任务说明与资源，先给模型简要信息，需要时加载详细内容，从而减少无关上下文。

Q06｜Agent 运行机制 #

面试官的问题（概括）： 请介绍一下 Agent 的运行机制。

我的回答（概括）： 我解释了一次请求执行的运行中、完成、失败、取消状态，以及 Session 保存对话历史、一个 Session 包含多次 Run。

Q07｜失败处理与重试 #

面试官的问题（概括）： 你们怎样管理任务状态？有没有失败重试机制？

我的回答（概括）： 我说失败时考虑降级，设置重试次数，超过次数后降级或提示人工介入；没有说出具体次数、错误分类或实现位置。

Q08｜两个项目的长任务恢复对比 #

面试官的问题（概括）： 两个项目都涉及长任务和断点恢复，它们的技术与设计有什么共同点？

我的回答（概括）： 我主要回答了高风险或写操作需要人工确认、执行前检查权限，以及审计相关内容。

Q09｜State、Checkpoint 与 Retry #

面试官的问题（概括）： 面试官澄清：问的是任务的 State、Checkpoint、Retry，你了解这些怎么做吗？

我的回答（概括）： 我说 trace 中可以看到 checkpoint，retry 是重试；随后转向保留输入版本和错误结果、定位需求/上下文/工具参数/API Key 问题，把 bad case 放入回归用例并人工复核。

Q10｜工业企业为什么使用 AI #

面试官的问题（概括）： 这是一家涉及高风险生产的企业，建立 AI 应用主要想解决什么问题？

我的回答（概括）： 我举设备管理任务：操作人员提供设备编号和时间范围，系统查询故障与维修记录，Agent 生成设备情况摘要，帮助人员了解设备情况并在系统中留存。

Q11｜故障信息从哪里来 #

面试官的问题（概括）： 故障是人工上报、系统自动上报，还是你们的功能主动巡检发现的？

我的回答（概括）： 我回答是当时的操作人员自行输入并告知。

Q12｜人员通过什么终端上报 #

面试官的问题（概括）： 人员是通过 App 还是其他操作终端上报？

我的回答（概括）： 我提到了某企业协作/知识平台，类比企业协作平台；随后面试官提到了工单系统。平台品牌在转录中不够清晰。

转录说明： 平台名称可能涉及知识协作与工单产品；本稿统一泛化，不把自动识别结果当成已确认名称。

Q13｜Agent 具体读取了什么 #

面试官的问题（概括）： 是不是人员提交工单后，Agent 读取页面或数据库数据，再汇总相关信息？

我的回答（概括）： 面试官概括了一条读取工单并汇总的流程，我连续表示认可，没有进一步说明数据访问方式。

Q14｜Agent 部署在哪里 #

面试官的问题（概括）： Agent 架设在哪里？是否在专门的服务器？企业是否有自己的算力和服务资源？

我的回答（概括）： 我回答接了某 Agent SDK 底座，没有说明部署位置。具体 SDK 名称无法可靠确认。

转录说明： 两轮转录均不足以确认 SDK 专有名称，保留“SDK 底座”这一可辨识意思。

Q15｜敏感数据是否外传 #

面试官的问题（概括）： 从业务系统读取资料再交给 Agent，会不会涉及敏感数据外传？

我的回答（概括）： 我回答这是校企合作项目，要求在传递信息前进行脱敏。

Q16｜校企试点还是生产使用 #

面试官的问题（概括）： 最后只是校企试点，还是已经投产、正常使用？

我的回答（概括）： 我说负责人告诉我已经用上了，觉得效果还可以；没有提供具体用户、验收或使用数据。

Q17｜数十个 MCP 工具如何产生 #

面试官的问题（概括）： 简历提到数十个 MCP 工具，是 Agent 自动写的，还是你们写的？

我的回答（概括）： 我回答有自动生成的，也有自己写的，没有说明生成方法和本人比例。

Q18｜手写工具与具体功能 #

面试官的问题（概括）： 你们手写的主要是什么？能举几个工具功能的例子吗？

我的回答（概括）： 我先说规定客户端与工具、资源服务之间的交互方法；被要求举功能例子后，说接口文档可能缺少权限信息和必填关系，需要人工处理。

Q19｜鉴权放在什么位置 #

面试官的问题（概括）： 鉴权是在工具里面，还是在平台上？工具也可能需要鉴权。

我的回答（概括）： 我回答放在工具上，没有展开。

Q20｜凭证是不是明文 #

面试官的问题（概括）： 鉴权信息是明文还是非明文？

我的回答（概括）： 我犹豫后回答“应该不是明文”，没有说明存储、传输或调用过程。

Q21｜三层权限链路的个人职责 #

面试官的问题（概括）： Agent→工具→业务系统的三层链路，是你完整设计的，还是只参与其中某个环节？

我的回答（概括）： 我请面试官重复问题；再次解释后，我停顿并说“我当时就是……”，没有形成完整回答。面试官随后让我回忆，不用着急。

Q22｜项目时间是否久远 #

面试官的问题（概括）： 项目是不是比较久了？

我的回答（概括）： 我先说虽然最近才结束，随后又说此前已经结束；具体月份已泛化。

Q23｜如何防止 Agent 越权 #

面试官的问题（概括）： 如何避免 Agent 出现越权、穿透权限边界等问题？

我的回答（概括）： 我回答在服务端与执行端强制校验，不能只在 prompt 写禁止越权；请求绑定可信用户身份，按角色与对象范围限制动作和可见数据，工具执行前再检查参数和权限。

Q24｜HTTPS 反向代理问题如何发现 #

面试官的问题（概括）： 简历里的 HTTPS 反向代理、Agent 与业务系统连通问题，是你发现的，还是别人反馈的？

我的回答（概括）： 我说是一线操作人员告诉我不能使用。没有进一步说出原始错误、请求路径、根因或定位过程。

Q25｜方案由谁解决 #

面试官的问题（概括）： 是你自己找到方案解决，还是请公司安全专家协助？

我的回答（概括）： 我回答和当时一起实习的同学协作，没有明确指出谁负责哪一部分。
